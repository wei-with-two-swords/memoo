# 第四章：创建项目

## 从概念到现实

经过前几章的理论准备，我们终于要开始动手实践了。在这一章中，我们将使用 Django 提供的命令行工具创建一个完整的博客项目。我会详细介绍创建项目的过程、项目的目录结构，以及各个文件的作用。

在正式开始之前，请确保你已经完成了第一章的准备工作：安装了 Python、创建并激活了虚拟环境、安装了 Django。如果你还没有完成这些步骤，请先回去完成它们。

## 创建 Django 项目

在命令行中，切换到你希望存放项目的目录。注意，这个目录应该是空的，或者至少是专门用于这个项目的。让我在当前工作目录下创建一个新的项目文件夹。

```bash
cd d:/Code/book
```

现在，我们使用 Django 提供的 `django-admin` 命令来创建一个新项目。Django 项目的名称可以是你喜欢的任何名字，不过最好使用有意义的名称，比如 `myblog`、`blog` 或者 `django_blog`。我们就用 `blog` 作为项目名称：

```bash
django-admin startproject blog
```

命令执行完毕后，你应该能在当前目录下看到一个名为 `blog` 的文件夹。让我查看一下这个文件夹的内容：

```
blog/
├── blog/           # 这是项目配置文件夹
│   ├── __init__.py
│   ├── settings.py
│   ├── urls.py
│   ├── wsgi.py
│   └── asgi.py
└── manage.py        # Django 管理脚本
```

这就是一个最基本的 Django 项目结构。虽然看起来很简单，但它已经包含了运行一个 Web 应用所需的所有核心配置。

## 目录结构详解

让我逐个解释这些文件和文件夹的作用。

### manage.py

这是 Django 提供的一个命令行工具，用于与项目进行各种交互。你可以使用它来运行开发服务器、创建数据库迁移、应用迁移、管理数据库、创建管理员账户等。

在使用 Django 的过程中，你会频繁地与这个文件打交道。比如，要启动开发服务器，你需要运行 `python manage.py runserver`；要创建数据库迁移，需要运行 `python manage.py makemigrations`。

### blog/ 文件夹（项目配置文件夹）

外层的 `blog/` 文件夹是项目的容器，它的名称无关紧要，你可以随意命名。Django 自动创建它只是为了提供一个方便的地方来存放项目文件。

内层的 `blog/` 文件夹是实际的 Python 包。这个文件夹里包含的都是 Python 模块，你可以用 `import blog.settings` 这样的方式来导入它们。

### blog/__init__.py

这是一个空文件，它的作用是将所在目录标记为一个 Python 包。如果没有这个文件，Python 就不会将这个目录当作一个可导入的模块。对于 Django 来说，这个文件通常是空的，但它的存在是必要的。

### blog/settings.py

这是整个 Django 项目的配置文件。它是一个 Python 模块，包含了项目的各种设置。

settings.py 是一个非常重要的文件，几乎所有的 Django 项目配置都在这里完成。在这个文件中，你可以找到数据库配置、应用程序注册、中间件配置、模板配置、静态文件配置等。

第一次创建项目时，Django 会使用一些默认值来填充这个文件。我们后续会根据需要修改其中的一些配置。

### blog/urls.py

这是 Django 项目的 URL 配置文件。在这个文件中，你可以定义 URL 模式和它们对应的视图函数（或类）。当用户访问某个 URL 时，Django 会根据这个配置来决定应该调用哪个视图来处理请求。

### blog/wsgi.py

这是 Web 服务器网关接口（WSGI）的配置文件。WSGI 是 Python 应用与 Web 服务器之间的标准接口。当项目部署到生产环境时，需要使用 WSGI 配置来连接应用服务器。

### blog/asgi.py

这是异步网关接口（ASGI）的配置文件。ASGI 是 WSGI 的继承者，支持异步处理，适合处理长连接和实时通信等功能。对于我们的博客项目，wsgi.py 足够了，但 asgi.py 也是一个合理的默认配置。

## 创建应用

现在项目已经创建好了，接下来我们需要创建一个"应用"（Application）。

在 Django 中，**项目（Project）** 和 **应用（App）** 是两个不同的概念。项目是一个完整的 Web 站点，而应用是项目中一个功能独立的模块。比如，一个大型网站可能有"用户管理"应用、"博客"应用、"论坛"应用等，它们组合在一起形成一个完整的项目。

对于我们的博客系统，我们可以创建一个名为 `article` 的应用来管理文章相关的功能。

在命令行中，进入 `blog` 项目目录，然后运行以下命令：

```bash
cd blog
python manage.py startapp article
```

命令执行完毕后，你应该能看到一个新的文件夹：

```
blog/
├── article/               # 新创建的应用
│   ├── __init__.py
│   ├── admin.py
│   ├── apps.py
│   ├── models.py
│   ├── views.py
│   ├── tests.py
│   └── migrations/
│       └── __init__.py
├── blog/
│   ├── __init__.py
│   ├── settings.py
│   ├── urls.py
│   ├── wsgi.py
│   └── asgi.py
└── manage.py
```

### article/ 文件夹结构

**__init__.py**：同样是 Python 包标识文件。

**admin.py**：用于注册模型到 Django Admin 后台的文件。

**apps.py**：应用的配置文件，定义了应用的一些基本元数据。

**models.py**：应用的数据模型文件，在这里定义数据库结构。

**views.py**：应用的视图文件，在这里编写处理请求的逻辑。

**tests.py**：用于编写单元测试的文件。

**migrations/**：数据库迁移文件夹，用于记录模型结构的变更历史。

## 项目与应用的关系

也许你现在对"项目"和"应用"的区别还有些模糊。让我用更形象的比喻来解释。

把 Django 项目想象成一栋写字楼，而应用就是写字楼里的各个公司。一个写字楼（项目）可以容纳多个公司（应用），每个公司（应用）都有自己独立的办公区域和功能。一个公司可以单独存在（如果你只想做一个简单的博客，那可能只需要一个应用），也可以与其他公司合作（多个应用共享数据和功能）。

对于我们的博客项目，目前来说只需要一个 `article` 应用就足够了。所有与文章相关的功能——包括文章、分类、标签的管理和展示——都可以放在这个应用里。

让我解释几个关键配置的作用。

**LANGUAGE_CODE 和 TIME_ZONE**：语言和时区配置。我们稍后会修改为中国时区。

## 注册应用

要让 Django 识别我们的 `article` 应用，需要在 `INSTALLED_APPS` 列表中添加它。打开 `settings.py`，找到 `INSTALLED_APPS` 部分，添加我们的应用：

```python
INSTALLED_APPS = [
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',
    
    # 添加我们的应用
    'article.apps.ArticleConfig',
]
```

或者，你也可以只写应用名称：

```python
INSTALLED_APPS = [
    # ... 其他应用
    'article',
]
```

两种写法都可以。`article.apps.ArticleConfig` 是应用的完整路径，`article` 是简写。Django 会自动找到对应的配置类。

## 配置中文和时区

既然我们要开发一个中文博客网站，就应该把语言和时区改成中国标准。还是在 `settings.py` 中：

```python
# 把 'en-us' 改成 'zh-hans'，启用中文界面
LANGUAGE_CODE = 'zh-hans'

# 把 'UTC' 改成 'Asia/Shanghai'，使用中国时区
TIME_ZONE = 'Asia/Shanghai'

# USE_TZ 设为 True，Django 会自动处理时区转换
USE_TZ = True
```

## 配置模板目录

默认情况下，Django 会从每个应用的 `templates` 文件夹中查找模板文件。但为了更好地管理，我们通常会在项目根目录下创建一个专门的 `templates` 文件夹来存放模板文件。

首先，在项目根目录（`blog/` 文件夹）下创建一个 `templates` 文件夹：

```
blog/
├── templates/          # 新创建的模板文件夹
├── article/
├── blog/
└── manage.py
```

然后，在 `settings.py` 中配置模板路径：

```python
TEMPLATES = [
    {
        'BACKEND': 'django.template.backends.django.DjangoTemplates',
        'DIRS': [BASE_DIR / 'templates'],  # 添加这行
        'APP_DIRS': True,
        'OPTIONS': {
            'context_processors': [
                'django.template.context_processors.debug',
                'django.template.context_processors.request',
                'django.contrib.auth.context_processors.auth',
                'django.contrib.messages.context_processors.messages',
            ],
        },
    },
]
```

`BASE_DIR / 'templates'` 是 Python 3 的 pathlib 语法，等价于 `os.path.join(BASE_DIR, 'templates')`。

## 创建静态文件目录

除了模板文件，我们还需要一个地方来存放 CSS、JavaScript、图片等静态文件。在项目根目录下创建一个 `static` 文件夹：

```
blog/
├── static/            # 新创建的静态文件夹
├── templates/
├── article/
├── blog/
└── manage.py
```

在 `static` 文件夹中，再创建一个 `css` 子文件夹，用于存放 CSS 文件：

```
blog/
├── static/
│   └── css/           # 存放 CSS 文件
├── templates/
├── article/
├── blog/
└── manage.py
```

## 常见问题

**Q: 运行 `django-admin startproject` 报错"不是内部或外部命令"怎么办？**

A: 确保你已经正确安装了 Django，并且激活了虚拟环境。试试运行 `pip list` 看看 Django 是否在列表中。如果不在，运行 `pip install django` 安装它。

**Q: 如何查看 Django 的版本？**

A: 运行 `django-admin --version` 或在 Python 中运行 `import django; print(django.get_version())`。

**Q: 可以使用中文作为项目名吗？**

A: 理论上可以，但不推荐。Python 包名推荐只使用 ASCII 字符，包括英文字母、数字和下划线。建议使用英文名称。

**Q: 可以在现有文件夹中创建项目吗？**

A: 可以。使用 `django-admin startproject blog .` 命令可以在当前目录创建项目（注意末尾的点）。不过最好还是创建一个新的空目录。
