# 第二章：项目需求分析

## 从想象到图纸

在前面的章节中，我们完成了开发环境的搭建。现在，是时候让思绪从技术细节中抽离出来，好好思考一下我们要构建的这个博客系统究竟是什么模样。

很多初学者容易犯的一个错误是：拿到一个需求就开始写代码，写着写着发现这个功能不对，那个逻辑有问题，推倒重来，浪费了大量时间。造成这种状况的原因，往往是在动手之前没有充分分析需求。磨刀不误砍柴工，在开始编码之前，我们先用一整章的篇幅来好好分析一下这个博客系统的需求。

## 博客系统是什么

在开始分析之前，让我们先回顾一下博客的本质。博客（Blog）是 Weblog 的缩写，中文译作"网络日志"。它是一种由个人管理、定期更新的网站，通常以倒序排列的文章为主要内容。

一个典型的博客页面，你在浏览器中看到的可能是这样的：顶部有一个漂亮的导航栏，展示网站名称和一些链接；导航栏下方是最新发布的文章列表，每篇文章有标题、摘要、发布日期、作者、分类和标签等信息；点击某篇文章的标题，就能进入文章的详细内容页面；在网站的某个角落，可能还有一个搜索框，方便访客查找特定内容。

当然，这只是一个最基础的博客样式。现实中的博客可能还要复杂得多：有的支持多作者，有的有评论系统，有的有点赞功能，有的支持文章打赏，有的有用户订阅和邮件通知功能......

对于我们这个教程项目，我会选择一条恰到好处的功能边界：足够完整，能够展示 Django 的各种特性；但又不会过于庞大，让人望而生畏。我们的博客系统将包含以下核心功能：

- 文章的发布、编辑和删除（通过管理员后台）
- 文章的分类和标签管理
- 文章的展示，包括列表页和详情页
- 按分类查看文章
- 按标签查看文章
- 文章搜索功能
- 富文本编辑支持
- 美观的响应式前端界面

## 功能模块划分

让我们更系统地梳理一下这个博客系统的功能。可以从两个维度来划分：一是使用者角色，二是功能类型。

### 按使用者角色划分

**访客（未登录用户）**：这是博客网站的主要使用者。他们可以浏览网站首页，查看文章列表，点击阅读文章详情，通过标签或分类筛选文章，使用搜索功能查找特定内容。

**管理员（网站运营者）**：负责博客内容的日常维护。他们通过 Django 自带的 Admin 后台登录，撰写新文章，编辑或删除已有文章，管理文章分类和标签，添加或修改网站基本信息。

### 按功能类型划分

**内容管理模块**：这是博客系统的核心。涉及文章的增删改查、分类管理、标签管理等。在这个模块中，我们要处理的核心数据对象包括：文章（Post）、分类（Category）、标签（Tag）。

**展示模块**：负责将内容以美观的形式呈现给访客。包括首页、文章列表页、文章详情页、分类归档页、标签归档页、搜索结果页等。

**辅助模块**：为用户提供更好的使用体验。包括全站搜索、文章分页、热门文章推荐（虽然本书可能不实现，但了解有这个方向）等。

## 页面设计分析

现在让我们从页面角度来梳理一下需要实现的功能。

### 首页（Home Page）

首页是网站的"门面"，是访客了解网站的第一印象。一个好的首页应该能够：

- 清晰展示网站名称和定位（通常在顶部导航栏）
- 快速传达网站的主要内容（最近的更新）
- 提供清晰的导航路径，让访客能够方便地找到自己感兴趣的内容

我们的首页将展示网站的最新文章列表，每篇文章以卡片形式呈现，包含标题、摘要、发布日期、分类和标签信息。首页还会展示网站的导航菜单，包括分类列表和标签列表。

### 文章列表页（Article List）

当访客点击某个分类或标签时，会进入相应的文章列表页。这个页面只显示属于该分类或标签的文章，其他逻辑与首页类似。

### 文章详情页（Article Detail）

点击文章标题后进入的页面，用于展示文章的完整内容。除了文章主体外，详情页通常还会显示文章发布日期、作者、分类、标签等信息。

### 搜索功能

访客可以在搜索框中输入关键词，系统会返回包含该关键词的文章列表。搜索应该能够匹配文章标题和正文内容。

## 数据模型设计

在需求分析阶段，我们不需要考虑具体的数据库表结构（那属于数据库设计阶段），但我们需要明确需要管理哪些数据对象。

### 文章（Post）

这是博客系统最核心的数据。一篇文章应该包含：

- **标题**：文章的名字，用于在列表页显示和搜索匹配
- **正文**：文章的具体内容，这是最重要的部分
- **摘要**：文章的简短描述，用于在列表页展示，访客可以通过摘要判断是否要点击阅读完整文章
- **发布时间**：文章公开的时间
- **修改时间**：文章最后修改的时间
- **分类**：每篇文章必须属于一个分类
- **标签**：每篇文章可以有多个标签
- **作者**：文章由谁撰写（我们假设只有一个管理员用户，暂时不考虑多作者）
- **浏览量**：文章被访问的次数（可选功能）

### 分类（Category）

分类用于对文章进行一级组织。分类应该包含：

- **名称**：分类的显示名称
- **slug**：URL 中使用的标识符，通常是名称的英文或拼音形式

一个博客系统通常有多少个分类？我见过只有三五个的小博客，也见过几十个分类的资讯网站。对于我们的教程博客，我建议设置 5-10 个分类比较合适，比如：技术分享、生活感悟、读书笔记、编程教程、工具推荐等。

### 标签（Tag）

标签是对文章的更细粒度组织。与分类不同，一篇文章可以同时拥有多个标签。标签应该包含：

- **名称**：标签的显示名称
- **slug**：URL 中使用的标识符

标签的数量通常比分类多得多，也更加灵活。访客可以通过点击某个标签，看到所有包含该标签的文章。

## 用户交互流程

让我们用文字描述一下典型的用户交互流程，这样可以更直观地理解系统的运作方式。

### 访客浏览流程

**流程一：浏览首页**

1. 访客打开博客网址，首先看到的是首页
2. 首页展示最新发布的文章列表（假设每页显示 10 篇）
3. 每篇文章显示标题、摘要、发布日期、分类和标签
4. 访客可以点击"阅读全文"或文章标题，进入文章详情页

**流程二：按分类浏览**

1. 访客点击导航栏中的某个分类名称
2. 系统显示该分类下的所有文章
3. 如果文章数量较多，会进行分页
4. 访客可以继续阅读，或返回首页

**流程三：按标签浏览**

1. 访客点击文章卡片上的某个标签
2. 系统显示所有包含该标签的文章
3. 后续流程与按分类浏览类似

**流程四：搜索文章**

1. 访客在搜索框输入关键词
2. 点击搜索按钮或按回车
3. 系统返回匹配的文章列表
4. 如果没有找到匹配的文章，显示"未找到相关结果"提示

### 管理员工作流程

**流程一：登录后台**

1. 管理员访问管理后台地址（/admin）
2. 输入用户名和密码
3. 验证通过后进入管理后台首页

**流程二：撰写文章**

1. 在后台点击"文章"模块的"添加"按钮
2. 进入文章编辑页面
3. 填写文章标题、正文、摘要
4. 选择或创建分类
5. 选择或创建标签
6. 点击"保存"按钮发布文章

**流程三：管理文章**

1. 在文章列表页面，可以看到所有文章
2. 可以搜索、筛选文章
3. 点击文章可以进入编辑页面
4. 可以删除不需要的文章

## 需求文档的价值

到这里，我们已经对博客系统的需求有了比较清晰的认知。让我把分析的结果整理成一份简单的需求文档。

这份文档不需要多么正式，但它是一个重要的里程碑。在正式开发之前，回顾这份文档可以帮助我们：

- 明确开发目标，避免偏离方向
- 估计工作量，合理安排时间
- 与他人沟通时有据可依
- 在开发过程中遇到决策时作为参考

```
博客系统需求文档 v1.0
============================

一、系统概述
-----------
本系统是一个基于 Django 框架的博客网站，用于分享技术文章和生活感悟。

二、用户角色
-----------
1. 访客：浏览网站、阅读文章的普通用户
2. 管理员：管理网站内容的运营人员

三、功能需求
-----------
【内容管理】
- 文章发布、编辑、删除
- 分类管理（增删改查）
- 标签管理（增删改查）
- 富文本编辑器支持

【内容展示】
- 网站首页展示最新文章
- 文章详情页展示完整内容
- 按分类查看文章列表
- 按标签查看文章列表
- 文章搜索功能
- 文章分页功能

四、数据模型
-----------
- 文章（Post）：标题、正文、摘要、发布时间、修改时间、分类、标签、作者、浏览量
- 分类（Category）：名称、slug
- 标签（Tag）：名称、slug

五、非功能需求
-------------
- 响应式设计，适配手机和电脑
- 页面加载速度适中
- 代码结构清晰，易于维护
```

## 技术选型

在开始编码之前，我还想简单说一下技术选型的问题。

**后端框架**：毫无疑问是 Django。Django 的 MTV 架构非常适合开发这种内容管理系统，而且 Django 自带的 Admin 后台可以让我们几乎零成本地获得一个功能完善的内容管理界面。

**数据库**：我们使用 Django 默认的 SQLite 数据库。这是一个轻量级的数据库，非常适合小型项目和个人项目。对于我们的博客系统来说，SQLite 的性能完全够用。如果以后项目规模扩大，可以很方便地迁移到 PostgreSQL 或 MySQL。

**前端模板**：使用 Django 原生的模板引擎。它足够强大，能够满足我们所有的需求，而且与 Django 无缝集成。

**富文本编辑器**：我们选择使用 Summernote。它是一个基于 Bootstrap 的简洁美观的富文本编辑器，安装和集成都很方便。

**前端样式**：我们将使用一个简洁美观的 CSS 框架，比如 Bootstrap 或者 Pure.css，来保证页面的美观和响应式布局。

## 写在需求分析之后

到这里，需求分析的工作就告一段落了。你可能觉得这一章没有写任何代码，有点无聊。但我要告诉你的是，需求分析是软件开发中最容易被低估的环节。很多经验丰富的开发者都有这样的体会：花在需求分析上的每一分钟，在开发阶段都能节省十分钟甚至更多。

接下来的章节中，我们将开始实际动手。下一章，我们会讨论数据库的设计，这是从需求到实现的关键一步。数据库设计的好坏，直接影响后续开发的效率和质量。

在开始下一章之前，我建议你再仔细读一遍这一章的内容，闭上眼睛想象一下你脑海中的博客系统是什么样子。如果你有什么想法与上面的分析不符，或者有什么功能是我没有提到但你觉得很重要的，记下来，我们会在后续的开发和优化中加入它们。
