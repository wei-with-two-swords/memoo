# 第六章：欢迎页面

## Django 的 MTV 模式

在正式创建欢迎页面之前，我想先花一点时间介绍 Django 的核心工作模式。理解了这个工作模式，你就能理解 Django 项目中代码的组织方式，以及为什么我们要这样组织代码。

Django 采用的是 MTV 模式，即 Model（模型）、Template（模板）和 View（视图）。这是 Django 对经典 MVC 模式的另一种诠释。

**Model（模型）**：负责与数据库交互。它定义了数据的结构和行为。在我们的博客系统中，Post、Category、Tag 就是模型。

**Template（模板）**：负责页面的展示。它是一种 HTML 文件，使用 Django 模板语言来动态生成内容。模板定义了页面的结构和外观。

**View（视图）**：负责业务逻辑。它接收用户的请求，从模型获取数据，然后选择合适的模板来渲染页面。视图是连接模型和模板的桥梁。

当用户访问一个 URL 时，Django 的工作流程是这样的：

1. URL 调度器（URLconf）根据请求的 URL，匹配到对应的视图函数
2. 视图函数处理请求，可能需要访问数据库获取数据
3. 视图函数将数据传递给模板，让模板渲染成 HTML
4. 模板将渲染后的 HTML 返回给用户

这个流程看起来很简单，但正是这种简洁的设计，让 Web 开发变得高效而有序。

## URL 配置

Django 的 URL 配置存储在 urls.py 文件中。当用户访问网站的某个页面时，Django 会根据这个配置来决定调用哪个视图。

Django 使用的是"基于正则表达式的 URL 分发器"。这意味着 URL 被定义为 Python 正则表达式，匹配到的部分会被捕获并传递给视图函数。

### 创建 URL 配置

首先，让我们在 article 应用中创建一个 urls.py 文件：

```python
# article/urls.py

from django.urls import path
from . import views

app_name = 'article'

urlpatterns = [
    path('', views.index, name='index'),
]
```

这里导入了 `path` 函数，它是最常用的 URL 模式类型。`path` 函数接受以下参数：

- **route**：URL 模式，如 `''` 表示根路径，`'article/'` 表示 article 路径
- **view**：对应的视图函数
- **name**：URL 的名称，用于在模板中反向引用

### 包含应用 URL

现在，我们需要在项目的主 urls.py 中包含 article 应用的 URL：

```python
# blog/urls.py

from django.contrib import admin
from django.urls import path, include
from django.conf import settings
from django.conf.urls.static import static

urlpatterns = [
    path('admin/', admin.site.urls),
    path('', include('article.urls', namespace='article')),
]

# 添加媒体文件的 URL（仅开发环境使用）
if settings.DEBUG:
    urlpatterns += static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
```

注意 `namespace='article'` 参数，它为 article 应用的 URL 指定了一个命名空间。这是 Django 推荐的做法，可以避免不同应用之间的 URL 名称冲突。

## 编写视图函数

视图函数是 Python 函数，接收 HTTP 请求作为参数，返回 HTTP 响应。最简单的情况下，视图函数可以返回一个字符串作为响应。

打开 article/views.py，编写第一个视图函数：

```python
# article/views.py

from django.http import HttpResponse

def index(request):
    return HttpResponse('欢迎访问我的博客！')
```

这是一个最简单的视图函数。当用户访问首页时，会看到浏览器显示"欢迎访问我的博客！"这几个字。

## 启动服务器测试

现在让我们测试一下 URL 配置是否正确。启动开发服务器：

```bash
python manage.py runserver
```

打开浏览器，访问 http://127.0.0.1:8000/。你应该能看到"欢迎访问我的博客！"的文字。

这说明我们的 URL 配置已经生效了！用户访问根路径 `''`，Django 匹配到了 `path('', views.index, ...)` 这个模式，然后调用 `views.index` 函数，返回了我们预设的文字。

## 使用模板渲染页面

虽然 `HttpResponse` 可以返回文字，但实际的网页是 HTML 页面，包含复杂的结构。我们需要使用模板来渲染页面。

首先，在 templates 文件夹中创建一个 article 子文件夹，用于存放 article 应用的所有模板：

```
blog/
├── templates/
│   └── article/       # 新创建的文件夹
│       └── index.html
├── static/
│   └── css/
├── article/
├── blog/
└── manage.py
```

然后，创建一个简单的 HTML 文件：

```html
<!-- templates/article/index.html -->

<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>我的博客</title>
</head>
<body>
    <h1>欢迎访问我的博客！</h1>
    <p>这是一个基于 Django 开发的博客系统。</p>
</body>
</html>
```

现在，修改视图函数，使用模板来渲染页面：

```python
# article/views.py

from django.shortcuts import render

def index(request):
    return render(request, 'article/index.html')
```

`render` 是 Django 提供的快捷函数，它接受请求对象、模板路径和上下文数据（可选），返回渲染后的 HTTP 响应。

刷新浏览器，你应该能看到一个新的页面，包含了我们在 HTML 文件中定义的内容。

## Django 的模板搜索路径

Django 寻找模板的路径有两个来源：

1. **settings.py 中 TEMPLATES 的 DIRS 配置**：我们之前配置的 `[BASE_DIR / 'templates']`
2. **每个应用的 templates 文件夹**：Django 会自动在已安装应用的目录下寻找 templates 文件夹

由于我们在 TEMPLATES 配置中设置了 `'APP_DIRS': True`，而且我们的模板路径是 `templates/article/index.html`，Django 会按以下顺序搜索这个模板：

1. `项目根目录/templates/article/index.html`
2. `article/templates/article/index.html`（如果存在）

这两种方式都是可行的。我个人更倾向于第一种，将所有模板放在项目的 templates 文件夹中，这样更易于管理。但也有很多人更喜欢将模板放在各自应用目录下，因为这样应用的代码更加自包含。

无论选择哪种方式，关键是保持一致性。整个项目使用同一种组织方式，不要混用。

## 传递数据到模板

目前我们的页面是静态的，所有内容都写死在 HTML 中。但在实际应用中，页面的内容通常是动态生成的。我们需要能够从视图向模板传递数据。

修改视图函数：

```python
# article/views.py

from django.shortcuts import render

def index(request):
    context = {
        'site_name': '我的技术博客',
        'welcome_message': '欢迎来到这里，分享我的技术心得！',
        'categories': ['Python', 'Django', 'Web开发', '读书笔记'],
    }
    return render(request, 'article/index.html', context)
```

修改模板来显示这些数据：

```html
<!-- templates/article/index.html -->

<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>{{ site_name }}</title>
</head>
<body>
    <h1>{{ site_name }}</h1>
    <p>{{ welcome_message }}</p>
    
    <h2>文章分类</h2>
    <ul>
        {% for category in categories %}
            <li>{{ category }}</li>
        {% endfor %}
    </ul>
</body>
</html>
```

刷新浏览器，你会看到：
- 标题和正文使用了 `{{ site_name }}` 和 `{{ welcome_message }}` 变量
- 分类列表使用了 `{% for %}` 模板标签循环遍历

这就是 Django 模板语言的基本用法。双大括号 `{{ }}` 用于输出变量值，`{% %}` 用于执行逻辑语句，如循环和条件判断。

## Django 模板引擎基础

Django 的模板语言被称为"Django Template Language"（DTL），它被设计成易于学习和使用，同时又足够强大来处理复杂的页面逻辑。

### 变量

变量使用双大括号包裹：`{{ variable_name }}`

变量可以是：
- Python 对象
- 字典的键
- 列表的索引
- 对象属性

Django 会自动处理这些访问，自动调用适当的 Python 方法。比如 `{{ article.title }}` 会被解析为 `article.title` 或 `article['title']`。

### 标签

标签使用 `{% %}` 包裹，它们控制模板的行为。

**条件标签**：
```html
{% if user.is_authenticated %}
    <p>欢迎，{{ user.username }}！</p>
{% else %}
    <p>请登录</p>
{% endif %}
```

**循环标签**：
```html
{% for item in item_list %}
    <p>{{ item }}</p>
{% empty %}
    <p>列表为空</p>
{% endfor %}
```

`{% empty %}` 是 for 循环特有的，当列表为空时执行。

**模板继承**：
```html
{% block content %}
    <!-- 内容块 -->
{% endblock %}
```

模板继承是 Django 模板系统最强大的功能之一。我们可以定义一个基础模板，然后让其他模板继承它，只覆盖需要自定义的部分。

### 过滤器

过滤器用于修改变量的输出格式：

```html
{{ name|lower }}          # 转小写
{{ date|date:"Y-m-d" }}   # 格式化日期
{{ text|truncatewords:30 }}  # 截断单词
{{ html|safe }}           # 标记为安全，不转义 HTML
```

过滤器可以链式调用：`{{ text|lower|truncatewords:10 }}`

### 注释

```html
{# 这是一个注释，不会被渲染 #}

{% comment %}
    多行注释
{% endcomment %}
```

## 创建一个基础模板

在实际项目中，我们通常会创建一个基础模板，定义整个站点的通用结构（头部、导航、底部等），然后让其他页面继承这个基础模板。

创建 `templates/article/base.html`：

```html
<!-- templates/article/base.html -->

<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>{% block title %}我的博客{% endblock %}</title>
    <link rel="stylesheet" href="/static/css/style.css">
</head>
<body>
    <header>
        <nav>
            <a href="/">{{ site_name }}</a>
            <ul>
                <li><a href="/">首页</a></li>
                <li><a href="{% url 'article:index' %}">博客</a></li>
            </ul>
        </nav>
    </header>
    
    <main>
        {% block content %}
        <!-- 页面内容会放在这里 -->
        {% endblock %}
    </main>
    
    <footer>
        <p>&copy; 2024 我的博客. All rights reserved.</p>
    </footer>
</body>
</html>
```

然后，修改首页模板继承基础模板：

```html
<!-- templates/article/index.html -->

{% extends 'article/base.html' %}

{% block title %}首页 - 我的博客{% endblock %}

{% block content %}
<h1>{{ site_name }}</h1>
<p>{{ welcome_message }}</p>

<h2>文章分类</h2>
<ul>
    {% for category in categories %}
        <li>{{ category }}</li>
    {% endfor %}
</ul>
{% endblock %}
```

刷新浏览器，页面看起来应该和之前一样，但实际上它的结构已经更合理了。我们定义了一个可复用的基础模板，其他页面可以方便地继承它。

## URL 的反向解析

在模板中，我们使用了 `{% url 'article:index' %}` 来生成 URL。这叫做 URL 的反向解析或反向查找。

为什么要这样做，而不是直接写 `/` 或 `/article/` 这样的 URL 呢？

原因是：URL 可能会随着项目的变化而改变。如果你在多个地方写死了 URL，后来需要修改 URL 结构，那就要改很多地方。而使用反向解析，你只需要修改 urls.py 中的 URL 配置，所有引用这个 URL 的地方都会自动更新。

`article:index` 中的 `article` 是我们在 include 时指定的 namespace，`index` 是 URL 的 name。完整的格式是 `namespace:name`。

在视图中也可以进行反向解析：

```python
from django.shortcuts import reverse

def my_view(request):
    url = reverse('article:index')  # 返回 '/'
    url = reverse('article:article_detail', args=[1])  # 返回 '/article/1/'
```
