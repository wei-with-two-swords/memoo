# 第七章：创建数据库模型

## 从理论到实践

在前面的学习中，我们已经对数据库设计有了清晰的认识，知道了博客系统需要哪些数据模型。现在，是时候把这些设计转化为实际的代码了。

在 Django 中，数据模型是通过继承 `models.Model` 类来定义的。每一个继承自这个类的 Python 类，都对应数据库中的一张表。类中的每一个属性（字段），都对应表中的一列。

让我们开始编写博客系统的数据模型吧。

## 定义 Category 模型

首先，打开 article/models.py 文件，这是我们定义模型的地方。

在第三章中，我们已经详细分析过分类模型应该包含哪些字段。回顾一下：分类需要存储名称（name）、别名（slug）和创建时间（created_time）。

```python
# article/models.py

from django.db import models
from django.utils import timezone


class Category(models.Model):
    """文章分类模型"""
    
    name = models.CharField('分类名称', max_length=100)
    slug = models.SlugField('URL别名', unique=True)
    created_time = models.DateTimeField('创建时间', default=timezone.now)
    
    class Meta:
        verbose_name = '分类'
        verbose_name_plural = '分类'
        ordering = ['name']
    
    def __str__(self):
        return self.name
```

让我详细解释每一部分的含义。

### 字段定义

**CharField**：固定长度的字符串字段。我们用它来存储分类名称。`max_length=100` 限制了最大长度为 100 个字符。

**SlugField**：一种特殊的 CharField，专门用于存储 URL 中使用的标识符。Django 会自动验证它的值只包含字母、数字、下划线和中划线。`unique=True` 表示这个值在整个表中必须唯一。

**DateTimeField**：日期时间字段。`default=timezone.now` 设置了默认值为当前时间。`timezone.now` 是 Django 提供的获取当前时区时间的方法，比 `datetime.now` 更安全。

### Meta 类

Meta 类用于定义模型的元数据（关于数据的数据）。这里我们定义了：

**verbose_name 和 verbose_name_plural**：这是模型在 Admin 后台中显示的名称。`verbose_name` 是单数形式，`verbose_name_plural` 是复数形式。Django 会自动在它们之间添加 's' 来创建复数形式，但为了更好地支持中文，我们显式地指定了复数形式。

**ordering**：指定默认的排序方式。这里指定按 name 升序排列。在查询分类时，如果没有指定排序方式，会按照这个顺序返回。

### __str__ 方法

`__str__` 方法定义了模型对象的字符串表示。当我们在 Admin 后台或其他地方需要显示一个分类对象时，会调用这个方法。Django 会在很多地方使用这个返回值，比如在关系中选择对象时显示的下拉列表。

### 外键引用的处理

等等，你可能注意到了，在 Post 模型中会引用 Category，但这里我们并没有在 Category 中添加任何关于 Post 的引用。这是 Django ORM 的设计哲学：**谁持有外键，谁负责定义关系**。由于一篇文章属于一个分类，所以外键定义在 Post 模型中，而不是 Category 中。

## 定义 Tag 模型

标签模型与分类模型非常相似。唯一的区别是，它们在业务上代表不同的事物。

```python
class Tag(models.Model):
    """文章标签模型"""
    
    name = models.CharField('标签名称', max_length=100)
    slug = models.SlugField('URL别名', unique=True)
    created_time = models.DateTimeField('创建时间', default=timezone.now)
    
    class Meta:
        verbose_name = '标签'
        verbose_name_plural = '标签'
        ordering = ['name']
    
    def __str__(self):
        return self.name
```

代码与 Category 模型几乎一模一样。重复的代码在编程中通常不是好习惯，但在模型定义这种场景下，简单的重复是可以接受的，因为每个模型可能需要在未来独立扩展。

## 定义 Post 模型

文章模型是整个博客系统的核心，也是最复杂的一个模型。

```python
class Post(models.Model):
    """文章模型"""
    
    # 基本信息
    title = models.CharField('标题', max_length=200)
    slug = models.SlugField('URL别名', unique=True)
    content = models.TextField('正文')
    excerpt = models.CharField('摘要', max_length=500, blank=True)
    
    # 时间信息
    created_time = models.DateTimeField('创建时间', default=timezone.now)
    modified_time = models.DateTimeField('修改时间', auto_now=True)
    
    # 统计信息
    views = models.PositiveIntegerField('浏览量', default=0)
    
    # 关系
    category = models.ForeignKey(
        Category,
        on_delete=models.CASCADE,
        verbose_name='分类',
        related_name='posts'
    )
    tags = models.ManyToManyField(
        Tag,
        blank=True,
        verbose_name='标签',
        related_name='posts'
    )
    
    class Meta:
        verbose_name = '文章'
        verbose_name_plural = '文章'
        ordering = ['-created_time']
    
    def __str__(self):
        return self.title
```

### 字段详解

**title**：文章标题，使用 CharField，限制最大长度 200 个字符。

**slug**：URL 别名，用于生成文章的 URL。

**content**：文章正文，使用 TextField。TextField 没有长度限制，适合存储可能很长的文章内容。

**excerpt**：文章摘要。`blank=True` 表示这个字段可以留空。Django 会区分两种"空"：`null` 针对数据库，`blank` 针对表单验证。对于文本字段，通常使用 `blank` 而不是 `null`。

**created_time**：创建时间。`default=timezone.now` 表示默认值为当前时间。Django 会自动记录这个时间，通常不需要手动设置。

**modified_time**：修改时间。`auto_now=True` 表示每次保存对象时，自动更新为当前时间。

**views**：浏览量。使用 `PositiveIntegerField`，只能存储正整数（大于等于 0）。

### 外键关系

**category**：分类外键。使用 `ForeignKey` 定义一对多关系。参数含义：

- `Category`：指向的模型
- `on_delete=models.CASCADE`：当分类被删除时，该分类下的所有文章也会被删除（级联删除）。这是最常用的删除行为。
- `related_name='posts'`：定义反向引用名称。设置后，可以通过 `category.posts.all()` 获取该分类下的所有文章。

**tags**：标签多对多关系。使用 `ManyToManyField` 定义多对多关系。参数含义：

- `Tag`：指向的模型
- `blank=True`：允许文章没有标签（一篇文章可以不关联任何标签）
- `related_name='posts'`：定义反向引用名称

### Meta 类

**ordering**：默认排序方式。`['-created_time']` 表示按创建时间倒序排列，也就是最新的文章排在最前面。前面的 `-` 表示降序。

## 完整模型代码

将三个模型整合到一起，我们得到了完整的模型定义：

```python
# article/models.py

from django.db import models
from django.utils import timezone


class Category(models.Model):
    """文章分类模型"""
    
    name = models.CharField('分类名称', max_length=100)
    slug = models.SlugField('URL别名', unique=True)
    created_time = models.DateTimeField('创建时间', default=timezone.now)
    
    class Meta:
        verbose_name = '分类'
        verbose_name_plural = '分类'
        ordering = ['name']
    
    def __str__(self):
        return self.name


class Tag(models.Model):
    """文章标签模型"""
    
    name = models.CharField('标签名称', max_length=100)
    slug = models.SlugField('URL别名', unique=True)
    created_time = models.DateTimeField('创建时间', default=timezone.now)
    
    class Meta:
        verbose_name = '标签'
        verbose_name_plural = '标签'
        ordering = ['name']
    
    def __str__(self):
        return self.name


class Post(models.Model):
    """文章模型"""
    
    # 基本信息
    title = models.CharField('标题', max_length=200)
    slug = models.SlugField('URL别名', unique=True)
    content = models.TextField('正文')
    excerpt = models.CharField('摘要', max_length=500, blank=True)
    
    # 时间信息
    created_time = models.DateTimeField('创建时间', default=timezone.now)
    modified_time = models.DateTimeField('修改时间', auto_now=True)
    
    # 统计信息
    views = models.PositiveIntegerField('浏览量', default=0)
    
    # 关系
    category = models.ForeignKey(
        Category,
        on_delete=models.CASCADE,
        verbose_name='分类',
        related_name='posts'
    )
    tags = models.ManyToManyField(
        Tag,
        blank=True,
        verbose_name='标签',
        related_name='posts'
    )
    
    class Meta:
        verbose_name = '文章'
        verbose_name_plural = '文章'
        ordering = ['-created_time']
    
    def __str__(self):
        return self.title
```

## 创建和应用迁移

模型定义好了，但数据库中还没有相应的表。我们需要创建迁移文件，然后应用迁移来创建表。

迁移（Migration）是 Django 用来记录模型变更的文件。每当你修改了模型，Django 就会生成一个新的迁移文件，记录这次的变更。然后，你把这个迁移文件应用到数据库，数据库的结构就会随之改变。

### 创建迁移

运行以下命令创建迁移：

```bash
python manage.py makemigrations
```

Django 会分析模型定义，生成一个迁移文件。命令的输出应该类似这样：

```
Migrations for 'article':
  article/migrations/0001_initial.py
```

### 查看迁移内容

Django 生成的迁移文件是一个 Python 文件，我们可以查看它的内容，了解 Django 会如何修改数据库：

```python
# article/migrations/0001_initial.py

from django.db import migrations, models
import django.db.models.deletion
import django.utils.timezone


class Migration(migrations.Migration):

    initial = True

    dependencies = [
    ]

    operations = [
        migrations.CreateModel(
            name='Category',
            fields=[
                ('id', models.BigAutoField(auto_created=True, primary_key=True, serialize=False, verbose_name='ID')),
                ('name', models.CharField(max_length=100, verbose_name='分类名称')),
                ('slug', models.SlugField(unique=True, verbose_name='URL别名')),
                ('created_time', models.DateTimeField(default=django.utils.timezone.now, verbose_name='创建时间')),
            ],
        ),
        migrations.CreateModel(
            name='Post',
            fields=[
                ('id', models.BigAutoField(auto_created=True, primary_key=True, serialize=False, verbose_name='ID')),
                ('title', models.CharField(max_length=200, verbose_name='标题')),
                ('slug', models.SlugField(unique=True, verbose_name='URL别名')),
                ('content', models.TextField(verbose_name='正文')),
                ('excerpt', models.CharField(blank=True, max_length=500, verbose_name='摘要')),
                ('created_time', models.DateTimeField(default=django.utils.timezone.now, verbose_name='创建时间')),
                ('modified_time', models.DateTimeField(auto_now=True, verbose_name='修改时间')),
                ('views', models.PositiveIntegerField(default=0, verbose_name='浏览量')),
                ('category', models.ForeignKey(on_delete=django.db.models.deletion.CASCADE, to='article.category', verbose_name='分类')),
                ('tags', models.ManyToManyField(to='article.tag', verbose_name='标签')),
            ],
        ),
        migrations.CreateModel(
            name='Tag',
            fields=[
                ('id', models.BigAutoField(auto_created=True, primary_key=True, serialize=False, verbose_name='ID')),
                ('name', models.CharField(max_length=100, verbose_name='标签名称')),
                ('slug', models.SlugField(unique=True, verbose_name='URL别名')),
                ('created_time', models.DateTimeField(default=django.utils.timezone.now, verbose_name='创建')),
            ],
        ),
        # 多对多关系的关联表...
    ]
```

你可以看到，Django 为我们生成了完整的 SQL 语句的 Python 版本。每一个 `CreateModel` 操作都对应创建一张表，每一个 `AddField` 操作都对应添加一个字段。

### 应用迁移

现在运行以下命令，将迁移应用到数据库：

```bash
python manage.py migrate
```

命令输出应该类似这样：

```
Operations to perform:
  Apply all migrations: admin, auth, contenttypes, sessions, article
Running migrations:
  Applying contenttypes.0001_initial... OK
  Applying auth.0001_initial... OK
  Applying admin.0001_initial... OK
  ...
  Applying article.0001_initial... OK
```

`Applying article.0001_initial... OK` 表示我们的模型迁移已经成功应用。Django 在 article 之外，还自动应用了其他内置应用的迁移（admin、auth、contenttypes、sessions）。这些内置应用也需要数据库表来存储它们的数据。

## 验证数据库

迁移成功后，Django 会在项目目录下创建一个 `db.sqlite3` 文件，这就是我们的 SQLite 数据库文件。你可以尝试查看一下数据库中的表：

```bash
python manage.py dbshell
```

这会打开 SQLite 的交互式命令行。在里面可以运行 SQL 语句：

```sql
-- 查看所有表
.tables

-- 查看文章表的结构
.schema article_post

-- 查看所有文章
SELECT * FROM article_post;
```

输入 `.quit` 可以退出数据库命令行。

## 模型的方法

除了字段，Django 模型还可以定义方法。方法可以访问模型实例的所有属性，也可以返回任何你需要的数据。

比如，我们可能需要获取文章的 URL，或者需要判断文章是否是最近发布的：

```python
class Post(models.Model):
    # ... 字段定义 ...
    
    def get_absolute_url(self):
        """返回文章的绝对URL"""
        from django.urls import reverse
        return reverse('article:detail', kwargs={'slug': self.slug})
    
    def increase_views(self):
        """增加浏览量"""
        self.views += 1
        self.save(update_fields=['views'])
```

这些方法可以在模板中调用，也可以在视图中调用。

## 常用字段参数

在使用模型的过程中，你会发现有很多场景需要用到各种字段参数。让我总结一下最常用的几个：

**verbose_name**：字段的友好名称，会显示在 Admin 后台和表单中。

**help_text**：字段的帮助文本，在表单中显示，提示用户应该如何填写。

**default**：字段的默认值。

**blank**：是否允许表单中留空（空字符串）。

**null**：是否允许数据库中存储 NULL 值。对于文本字段，通常使用 `blank=True, null=False`。

**choices**：字段的可选值，限制用户只能选择预定义的选项。

**db_index**：是否为该字段创建数据库索引，提升查询速度。
