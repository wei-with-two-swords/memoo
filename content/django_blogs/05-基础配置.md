# 第五章：基础配置

## 深入理解 settings.py

在上一章中，我们创建了第一个 Django 项目，并初步认识了项目结构。在启动开发服务器验证项目时，一切运行正常。Django 为我们生成了默认配置，这些配置对于一个简单的项目来说已经足够好了。

但既然我们要开发一个完整的博客系统，就不能止步于此。在这一章中，我们将深入了解 settings.py 中的各项配置，了解它们的作用，并进行适合博客系统的优化。同时，我还会分享一些实际项目中的最佳实践。

## settings.py 的整体结构

Django 的 settings.py 是一个普通的 Python 模块，它不是 JSON、YAML 或 XML，而是一个可以执行任意 Python 代码的文件。这种设计给了我们很大的灵活性：你可以在 settings.py 中导入其他模块、使用条件判断、甚至可以执行一些计算。

典型的 settings.py 包含以下几大块配置：

1. 基本路径配置
2. 安全密钥配置
3. 调试模式配置
4. 允许访问的域名配置
5. 已安装应用配置
6. 中间件配置
7. URL 配置
8. 模板配置
9. 数据库配置
10. 密码验证配置
11. 国际化配置
12. 静态文件配置
13. 其他杂项配置

让我们逐一深入了解。

## 基本路径配置

打开 settings.py，你首先会看到类似这样的代码：

```python
from pathlib import Path
import os

BASE_DIR = Path(__file__).resolve().parent.parent
```

这里的 `BASE_DIR` 代表项目根目录的绝对路径。Django 使用 `pathlib.Path` 来处理路径，这是一个比传统 `os.path` 更现代、更直观的方式。

`Path(__file__).resolve().parent.parent` 这行代码做了三件事：
1. `__file__` 获取当前 settings.py 文件的路径
2. `.resolve()` 将相对路径转换为绝对路径
3. `.parent.parent` 获取上两级目录，也就是项目根目录

其他路径配置通常都基于 `BASE_DIR` 来定义。比如：

```python
TEMPLATES_DIR = BASE_DIR / 'templates'
STATIC_DIR = BASE_DIR / 'static'
MEDIA_DIR = BASE_DIR / 'media'
```

这样做的好处是，无论项目部署在什么位置，这些路径都能正确指向项目内部的目录。

## 安全配置

```python
SECRET_KEY = 'django-insecure-xxxxx-xxxxx-xxxxx'
DEBUG = True
ALLOWED_HOSTS = []
```

**SECRET_KEY** 是 Django 用于安全加密的密钥，用于生成 CSRF token、Session 加密、密码哈希等。这个值必须保密，一旦泄露，攻击者就可以伪造用户的身份。

在开发环境中，默认的 SECRET_KEY 问题不大。但在部署到生产环境时，**必须修改为一个随机且安全的值**。可以使用以下命令生成一个安全的密钥：

```python
from django.core.management.utils import get_random_secret_key
print(get_random_secret_key())
```

**DEBUG** 模式开启时，Django 会显示详细的错误页面，方便开发者调试。但这个页面如果被普通用户看到，会泄露很多敏感信息，所以部署时必须关闭。

**ALLOWED_HOSTS** 用于指定哪些域名可以访问你的网站。这是一种安全措施，防止攻击者通过恶意构造的请求头来绕过安全限制。

开发环境下保持为空即可。生产环境下，需要填写真实的域名：

```python
ALLOWED_HOSTS = ['example.com', 'www.example.com']
```

如果想允许所有域名访问（仅限开发环境）：

```python
ALLOWED_HOSTS = ['*']
```

## 已安装应用配置

```python
INSTALLED_APPS = [
    'django.contrib.admin',  # Admin 后台
    'django.contrib.auth',    # 用户认证系统
    'django.contrib.contenttypes',  # 内容类型框架
    'django.contrib.sessions',      # 会话管理
    'django.contrib.messages',      # 消息框架
    'django.contrib.staticfiles',   # 静态文件管理
    
    # 我们的应用
    'article',
]
```

Django 自带了很多有用的应用：

**django.contrib.admin**：提供 Admin 管理后台功能。

**django.contrib.auth**：用户认证系统，包括用户、权限、组等。

**django.contrib.contenttypes**：内容类型框架，是 Django 内部很多功能的基础。

**django.contrib.sessions**：会话管理，用于在无状态的 HTTP 请求之间存储用户数据。

**django.contrib.messages**：消息框架，用于向用户显示一次性通知。

**django.contrib.staticfiles**：静态文件管理，负责收集静态文件并提供 URL 访问。

这些应用大多需要数据库支持，所以我们需要在数据库中创建它们需要的表。这就是为什么首次运行项目时，Django 会提示我们运行迁移命令。

## 中间件配置

中间件是 Django 处理请求和响应的"插件"系统。每个中间件负责一个特定的功能，按照配置的顺序依次处理请求和响应。

```python
MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    'django.contrib.sessions.middleware.SessionMiddleware',
    'django.middleware.common.CommonMiddleware',
    'django.middleware.csrf.CsrfViewMiddleware',
    'django.contrib.auth.middleware.AuthenticationMiddleware',
    'django.contrib.messages.middleware.MessageMiddleware',
    'django.middleware.clickjacking.XFrameOptionsMiddleware',
]
```

让我解释几个重要的中间件：

**SecurityMiddleware**：处理各种安全相关的功能，如 HTTPS 重定向、浏览器 XSS 防护等。

**SessionMiddleware**：处理会话，将用户的会话数据存储在服务端或 Cookie 中。

**CommonMiddleware**：提供一些通用功能，如 URL 重定向、URL 末尾斜杠处理等。

**CsrfViewMiddleware**：防止跨站请求伪造攻击。开启后，所有 POST、PUT、DELETE 等请求都需要携带 CSRF token。

**AuthenticationMiddleware**：处理用户认证，将用户信息附加到请求对象上。

**MessageMiddleware**：处理一次性消息，如"登录成功"、"文章已发布"等。

**XFrameOptionsMiddleware**：防止网站被嵌入到 iframe 中，避免点击劫持攻击。

## 数据库配置

```python
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.sqlite3',
        'NAME': BASE_DIR / 'db.sqlite3',
    }
}
```

对于我们的博客项目，默认的 SQLite 配置已经足够好了。SQLite 是一个轻量级的数据库，不需要额外的数据库服务器，非常适合小型项目和个人项目。

如果将来项目规模扩大，需要使用 MySQL 或 PostgreSQL，可以这样配置：

```python
# MySQL 配置
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.mysql',
        'NAME': 'blog_db',
        'USER': 'blog_user',
        'PASSWORD': 'your_password',
        'HOST': 'localhost',
        'PORT': '3306',
    }
}

# PostgreSQL 配置
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.postgresql',
        'NAME': 'blog_db',
        'USER': 'blog_user',
        'PASSWORD': 'your_password',
        'HOST': 'localhost',
        'PORT': '5432',
    }
}
```

## 模板配置

```python
TEMPLATES = [
    {
        'BACKEND': 'django.template.backends.django.DjangoTemplates',
        'DIRS': [BASE_DIR / 'templates'],
        'APP_DIRS': True,
        'OPTIONS': {
            'context_processors': [
                'django.template.context_processors.debug',
                'django.template.context_processors.request',
                'django.contrib.auth.context_processors.auth',
                'django.contrib.messages.context_processors.messages',
            ],
        },
    },
]
```

**DIRS**：模板文件的搜索目录列表。我们之前创建了 templates 文件夹并在这里配置了路径。

**APP_DIRS**：是否在已安装应用中的 templates 文件夹中搜索模板。对于我们的项目，设为 True 更好。

**context_processors**：模板上下文处理器，这是一个重要的概念。它定义了哪些变量会自动注入到每个模板的上下文中。比如：

- `debug`：在模板中可以使用 `DEBUG` 变量
- `request`：在模板中可以使用 `request` 对象
- `auth`：在模板中可以使用 `user` 和 `perms` 对象
- `messages`：在模板中可以使用 `messages` 消息列表

## 国际化配置

```python
LANGUAGE_CODE = 'zh-hans'
TIME_ZONE = 'Asia/Shanghai'
USE_I18N = True
USE_TZ = True
```

我们已经在上一章配置过这些了。简单解释：

**LANGUAGE_CODE**：网站的语言代码。`zh-hans` 表示简体中文。

**TIME_ZONE**：时区设置。`Asia/Shanghai` 是中国标准时间。

**USE_I18N**：是否启用国际化。开启后 Django 会支持多语言。

**USE_TZ**：是否启用时区支持。开启后 Django 会存储带时区的日期时间。

## 静态文件和媒体文件配置

```python
STATIC_URL = '/static/'
STATICFILES_DIRS = [BASE_DIR / 'static']

MEDIA_URL = '/media/'
MEDIA_ROOT = BASE_DIR / 'media'
```

**STATIC_URL**：静态文件在浏览器中访问的 URL 前缀。

**STATICFILES_DIRS**：静态文件的存放目录，告诉 Django 除了应用目录外还要去哪里找静态文件。

**MEDIA_URL** 和 **MEDIA_ROOT**：用于存放用户上传的文件，如文章的图片。Django 本身不提供这些文件的存储功能，需要配合 Web 服务器（如 Nginx）来提供服务。

## 设置最佳实践

### 使用环境变量

在实际项目中，通常有不同的配置环境：开发环境、测试环境、生产环境。一个好的做法是将敏感配置或环境相关配置放在环境变量中：

```python
import os

SECRET_KEY = os.environ.get('DJANGO_SECRET_KEY', 'default-key-for-dev')
DEBUG = os.environ.get('DJANGO_DEBUG', 'True') == 'True'
ALLOWED_HOSTS = os.environ.get('DJANGO_ALLOWED_HOSTS', '').split(',')
```

### 分离开发与生产配置

可以将配置分为多个文件：

```
blog/
├── settings/
│   ├── __init__.py
│   ├── base.py      # 通用配置
│   ├── dev.py       # 开发环境配置
│   └── prod.py      # 生产环境配置
```

然后在主配置文件中根据环境选择加载哪个：

```python
import os
env = os.environ.get('DJANGO_ENV', 'dev')

if env == 'prod':
    from .prod import *
else:
    from .dev import *
```

### 添加自定义配置

你可以在 settings.py 中添加任何自定义配置：

```python
# 每页显示的文章数量
ARTICLE_PAGINATE_BY = 10

# 文章摘要截断字数
EXCERPT_LENGTH = 200

# 富文本编辑器的配置
RICHTEXT_CONFIG = {
    'toolbar': 'full',
    'height': 300,
}
```

然后在代码中这样使用：

```python
from django.conf import settings

per_page = settings.ARTICLE_PAGINATE_BY
```

## 完整的基础配置

经过以上分析和调整，我们的 settings.py 大致是这样的：

```python
"""
Django settings for blog project.
"""

from pathlib import Path
import os

# Build paths inside the project like this: BASE_DIR / 'subdir'.
BASE_DIR = Path(__file__).resolve().parent.parent

# SECURITY WARNING: keep the secret key used in production secret!
# 生产环境请使用环境变量
SECRET_KEY = os.environ.get('DJANGO_SECRET_KEY', 'django-insecure-dev-key-change-in-production')

# SECURITY WARNING: don't run with debug turned on in production!
DEBUG = os.environ.get('DJANGO_DEBUG', 'True') == 'True'

ALLOWED_HOSTS = os.environ.get('DJANGO_ALLOWED_HOSTS', '*').split(',') if DEBUG else os.environ.get('DJANGO_ALLOWED_HOSTS', '').split(',')

# Application definition
INSTALLED_APPS = [
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',
    
    # 第三方应用
    'django_summernote',
    
    # 我们的应用
    'article',
]

MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    'django.contrib.sessions.middleware.SessionMiddleware',
    'django.middleware.common.CommonMiddleware',
    'django.middleware.csrf.CsrfViewMiddleware',
    'django.contrib.auth.middleware.AuthenticationMiddleware',
    'django.contrib.messages.middleware.MessageMiddleware',
    'django.middleware.clickjacking.XFrameOptionsMiddleware',
]

ROOT_URLCONF = 'blog.urls'

TEMPLATES = [
    {
        'BACKEND': 'django.template.backends.django.DjangoTemplates',
        'DIRS': [BASE_DIR / 'templates'],
        'APP_DIRS': True,
        'OPTIONS': {
            'context_processors': [
                'django.template.context_processors.debug',
                'django.template.context_processors.request',
                'django.contrib.auth.context_processors.auth',
                'django.contrib.messages.context_processors.messages',
            ],
        },
    },
]

WSGI_APPLICATION = 'blog.wsgi.application'

# Database
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.sqlite3',
        'NAME': BASE_DIR / 'db.sqlite3',
    }
}

# Password validation
AUTH_PASSWORD_VALIDATORS = [
    {
        'NAME': 'django.contrib.auth.password_validation.UserAttributeSimilarityValidator',
    },
    {
        'NAME': 'django.contrib.auth.password_validation.MinimumLengthValidator',
    },
    {
        'NAME': 'django.contrib.auth.password_validation.CommonPasswordValidator',
    },
    {
        'NAME': 'django.contrib.auth.password_validation.NumericPasswordValidator',
    },
]

# Internationalization
LANGUAGE_CODE = 'zh-hans'
TIME_ZONE = 'Asia/Shanghai'
USE_I18N = True
USE_TZ = True

# Static files (CSS, JavaScript, Images)
STATIC_URL = '/static/'
STATICFILES_DIRS = [
    BASE_DIR / 'static',
]

# Media files
MEDIA_URL = '/media/'
MEDIA_ROOT = BASE_DIR / 'media'

# Default primary key field type
DEFAULT_AUTO_FIELD = 'django.db.models.BigAutoField'

# Custom settings
ARTICLE_PAGINATE_BY = 10
EXCERPT_LENGTH = 200
```
